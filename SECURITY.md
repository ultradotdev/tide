# Security Policy

## Supported Versions

Security fixes are released for the latest minor version. Update to the newest release before reporting.

| Version | Supported |
| ------- | --------- |
| 0.11.x  | Yes       |
| < 0.11  | No        |

## Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability in Tide, please report it responsibly.

**Do not open a public GitHub issue for security vulnerabilities.**

### How to Report

Report it privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability** ([direct link](https://github.com/ultradotdev/tide/security/advisories/new)). You can also email **security@zorz.com**. Include:

- A description of the vulnerability
- Steps to reproduce the issue
- Potential impact
- Any suggested fixes (optional)

### What to Expect

- **Acknowledgment**: We will acknowledge receipt within 48 hours
- **Assessment**: We will investigate and assess the severity within 7 days
- **Resolution**: We aim to release a fix within 30 days for critical issues
- **Disclosure**: We will coordinate with you on public disclosure timing

### Scope

The following are in scope:

- The Tide application
- Build and distribution processes
- Dependencies with known vulnerabilities

The following are out of scope:

- Social engineering attacks
- Denial of service attacks
- Issues in third-party applications or services

## Security Best Practices

When using Tide:

- Keep Tide updated to the latest version
- Be cautious when opening files from untrusted sources
- Review LSP server configurations before enabling
- Use trusted terminal commands

Thank you for helping keep Tide secure.
