# Tide v0.13.0 Release Notes

Tide 0.13.0 opens the repository a file belongs to, reloads your themes as you edit them, moves sessions out of a folder named `rust`, and fixes the Codex session list on long histories along with several smaller problems.

## Changes

- **A path opens its repository.** `tide src/main.rs` used to open `src/` as the workspace. Tide now opens the nearest Git repository that contains the path, with the file open in it. A folder inside a repository opens the repository and shows that folder in the Explorer. A submodule opens the repository that contains it. Tide never opens your home folder as the workspace because a path is somewhere below it. A path outside any repository opens its folder, as before. A file you name now opens even when Tide restores a saved session.
- **Themes reload as you save them.** Editing a theme file in your themes folder applies it as soon as you save, as settings already did; adding or removing one updates the theme list. See [theme authoring](THEME_AUTHORING.md).
- **Sessions moved up a folder.** Tide 0.10.0 to 0.12.2 saved sessions in a `rust` folder inside the sessions folder. The first start of 0.13.0 moves them up, and moves any older files it finds there into `legacy/`. Nothing is overwritten. See [troubleshooting](troubleshooting.md).

## Fixes

- **Codex sessions load with very long previews.** `codex app-server` sends 100 sessions at a time on one line, each with a preview of its first message, which Codex does not shorten. A page could run to half a megabyte, twice the 256 KB Tide allowed, and the Agents sidebar showed "Codex native catalog: Codex app-server metadata output limit exceeded". Tide now accepts pages of that size.
- **Agents sidebar messages wrap.** A provider's status, such as an error or "No workspace sessions · 326 elsewhere · w associate", was cut off at the sidebar's edge. It now wraps onto up to four lines; Enter on it shows the whole message.
- **Listing sessions no longer creates Gemini or OpenCode data.** Tide asked the Gemini and OpenCode CLIs for their sessions even where they had never been used, and they created their data folders and database in your home folder. Tide now asks Gemini only once it has a session folder and knows the workspace, and OpenCode only once it has a database.
- **The status bar shows the real encoding.** It always said `UTF-8`. It now says `UTF-8 with BOM` for files that have one, and nothing for a file Tide had to read with replacement characters.
- **The command palette shows shortcuts your terminal can send.** In a terminal without the kitty keyboard protocol, such as Terminal.app, the palette listed keys like Ctrl+Shift+` that reach Tide as something else. Where a command has another key the terminal can send, the palette now shows that one.
- **Gemini accounts that can't use the CLI.** An account Gemini turns away for its plan was shown as "Not signed in", though signing in again doesn't help. It now shows "Account not eligible", and Enter explains.
- **Old saved passwords are removed.** Changing a saved database connection so it no longer uses its stored password left the old password in the keychain or secrets file. Tide now deletes it.

## Upgrading

- Homebrew: `brew update && brew upgrade tide`
- Install script: re-run it, or run Help: Check for Updates for the command.

Settings, key bindings and history from 0.12.2 carry over, and sessions move to their new folder on the first start.

See [getting started](getting-started.md), [configuration](reference/configuration.md), [troubleshooting](troubleshooting.md) and [security](../SECURITY.md).
